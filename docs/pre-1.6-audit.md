Аудит от 27 ноября 2026 года. Локальный main, GitHub main и последний релиз v1.5.3.1 совпали на коммите 86355737. Для навигации использован Graphify по тому же коммиту. Каждый вывод сверён с исходниками.

## Как устроен Hub

| Уровень | Контракт и ответственность |
| --- | --- |
| Windows | [desktop.py](../desktop.py#L17) запускает WPF, многопоточный HTTP-сервер, трей и наблюдение за буфером. |
| Интерфейс | [WPF](../native/file_pages.py#L580) и [браузер](../web/tools/diskmap.js#L478) используют один синхронный маршрут расчёта. |
| HTTP | [HubHandler](../server.py#L659) проверяет запрос и вызывает инструмент. В настольном режиме внешним клиентам доступны выделенные маршруты QR-Drop. |
| Файловые операции | [diskmap](../tools/diskmap.py#L217) агрегирует подпапки и файлы в корне, возвращает логические байты, счётчики, примеры ошибок и признак усечения. [files и remove_file](../tools/diskmap.py#L56) отдельно строят список и проверяют идентичность файлов перед удалением. [fileguard](../tools/fileguard.py#L107) и [trash](../tools/trash.py#L67) отвечают за проверку путей, перенос и восстановление. |
| Настройки и поставка | [preferences](../tools/preferences.py#L14) валидирует настройки и атомарно сохраняет JSON. [build.ps1](../windows/build.ps1) собирает Windows x64, [updater](../tools/updater.py) проверяет размер и SHA-256 установщика. |

## Benchmark Lab

Запуск из корня репозитория. Временный каталог должен существовать.

```powershell
New-Item -ItemType Directory -Force dist | Out-Null
.venv/Scripts/python.exe -m benchmarks.disk_map --temp-dir dist > dist/benchmark-pre-16.json
.venv/Scripts/python.exe -m benchmarks.disk_map --compare dist/benchmark-pre-16.json dist/candidate.json
```

Скрипт создаёт временные деревья файлов по 256 байт. Два больших набора содержат одинаковое число файлов, но имеют разную структуру. Каждый прогон выполняется в отдельном процессе. Скрипт сверяет число файлов и сумму байтов, сохраняет исходные результаты и медианы. Для scan кэш Hub пуст. Для scan-cached отдельный вызов прогревает кэш до запуска таймера. Кэш файловой системы Windows сохраняется.

Wall time и CPU time измеряют вызов функции. CPU % нормирован на одно логическое ядро. Пиковый working set относится ко всему процессу, включая запуск Python и прогрев в режиме scan-cached. Для Rust-воркера нужно учитывать время процесса и память отдельно, затем измерять полный запрос с суммарными ресурсами.

| 1. Python и задания | После этапа 0 сравнить потоковый обход с baseline. Добавить ограниченный реестр заданий, прогресс и кооперативную отмену. Синхронный маршрут сохранить для прежнего клиента. | Интерфейс показывает фазу, число обработанных записей и найденные байты. Пока общий объём неизвестен, прогресс без процента. Проверены суммарная память, время отмены и запуск из установщика. |

Предлагаемый контракт задания включает старт, чтение состояния по ID и отмену. Состояния — в очереди, выполняется, завершено, отменено, ошибка. Достаточно одного активного расчёта на окно с ограничением числа заданий на сервере и удалением завершённых записей по TTL. Результат завершённого задания сохраняет текущие поля ответа scan. WPF может использовать существующий обработчик ухода со страницы для запроса отмены. Синхронный HTTP-клиент продолжит видеть прежний формат.

Первая экспериментальная настройка принадлежит карте диска. В остальных инструментах пока нет зависимости от Rust. Перед выпуском проверить параллельные запросы, запоздалый ответ после отмены и перезапуск со включённым и выключенным экспериментом.

## Риски

- **Отмена ввода-вывода.** Кооперативная отмена ждёт возврата из системного вызова. Для отдельного процесса возможна ограниченная задержка с завершением только этого воркера. Это важно для зависших сетевых путей.
- **Windows-совместимость.** Reparse points, права доступа, длинные пути и порядок перечисления влияют на результаты. Сохранить учёт логических байтов, лимиты и различие полного и усечённого результата. Авторизация удаления, перенос и восстановление остаются в Python.
- **Кэш.** Для сравнения движков изолировать кэш по реализации и версии контракта. Отменённые и аварийные результаты не должны его обновлять.
- **Поставка.** Отдельный процесс изолирует падение и позволяет остановить воркер, но добавляет запуск и упаковку EXE. При отсутствии совместимого бинарника Hub должен запускаться и считать на Python. Перед поставкой проверить Windows x64, установщик и ZIP.

Штатные тесты карты диска дали 22 успешных проверки и одну пропущенную. Сетевые диски, пользовательские деревья и отрисовка WPF в baseline не входят. Rust ещё не измерялся.
