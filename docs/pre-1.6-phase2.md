# Hub Pre-1.6.x · Python Core

Работа выполнена поверх `86355737` (`v1.5.3.1`). На старте незакоммиченные файлы относились к предыдущему аудиту. [Первоначальный аудит](pre-1.6-audit.md) и [исходные замеры](../benchmarks/baseline-8635573.json) сохранены.

## Что исправлено

- `tools/diskmap.py` обрабатывает записи по мере чтения. При достижении лимита он читает максимум одну дополнительную запись, чтобы отличить полный результат от усечённого. Вложенность ограничена 60 уровнями. Закрываются все открытые итераторы, в том числе при отмене. Повторная проверка перед спуском выявляет папку, заменённую ссылкой или junction. Для неполного результата возвращаются общее число пропусков и до 25 примеров.
- Повторный расчёт из Hub читает актуальное состояние папки. Старый кэш с TTL 90 секунд был причиной воспроизведённой ошибки: после добавления файла на 5 байт повторный расчёт остался на 3 байтах. Кэш теперь используется только при явном запросе, как в сценарии Benchmark Lab. Неудачный, усечённый или отменённый обход не публикует результат в кэш.
- Корни локальных фиксированных и съёмных дисков можно посчитать через фоновое задание с самого ПК. Системные папки пропускаются. Для корня закрыты выдача списка файлов и авторизация удаления. Политика `fileguard` для остальных инструментов сохранена. Синхронный маршрут для прежнего клиента остался доступен для обычных папок.
- `tools/jobs.py` выделяет один слот для фоновой операции на сервер. Клиент показывает число пройденных записей, найденных файлов и байтов. Опрос продлевает срок жизни задания на 15 секунд. Кнопка отмены или выход со страницы запрашивают остановку. Если связь пропала, задание отменяется по истечении этого срока. Слот освобождается после завершения, а неполученный результат удаляется после истечения срока жизни. `server.py`, `desktop.py`, WPF и браузер используют этот механизм для карты диска.

## Benchmark Lab

Windows 11, Python 3.13.17, 12 логических процессоров, один том NTFS. По пять прогонов на сценарий и реализацию. В обоих случаях использовались одни и те же файлы, а порядок запуска менялся после каждой пары. Каждый замер выполнялся в отдельном процессе. Начальный обход начинается с пустым кэшем Hub. Полный повторный обход идёт после первого обхода, но с очищенным кэшем Hub. Третья группа измеряет отдельно попадание в кэш. Кэш Windows при этом сохраняется. `CPU` означает время процесса, а пик RAM — максимальный рабочий набор процесса вместе с Python и, в повторных сценариях, первым обходом. Процент одного ядра доступен в JSON. Для коротких операций он слишком чувствителен к дискретности счётчика.

| Сценарий | Файлов | Время до → после, мс | CPU до → после, мс | Пик RAM до → после, МиБ |
| --- | ---: | ---: | ---: | ---: |
| Вложенное дерево, первый обход | 2 000 | 22,77 → 22,84 | — | 22,86 → 22,55 |
| Вложенное дерево, полный повторный | 2 000 | 20,81 → 22,62 | — | 22,73 → 22,53 |
| Большое вложенное дерево, первый обход | 30 000 | 273,00 → 289,55 | 281,25 → 281,25 | 22,82 → 22,82 |
| Большое вложенное дерево, полный повторный | 30 000 | 266,95 → 289,95 | 265,63 → 296,88 | 22,78 → 22,56 |
| Большое вложенное дерево, попадание в кэш | 30 000 | 3,19 → 3,61 | — | 22,85 → 22,72 |
| Широкая папка, первый обход | 30 000 | 66,55 → 63,74 | 62,50 → 62,50 | 56,06 → 22,73 |
| Широкая папка, полный повторный | 30 000 | 65,11 → 63,38 | 62,50 → 62,50 | 56,12 → 22,62 |
| Широкая папка, список файлов | 30 000 | 1899,50 → 1668,65 | 1890,63 → 1671,88 | 54,11 → 53,84 |

В каждом прогоне совпали число файлов и сумма логических байтов. Для набора из 2 000 файлов получено 512 000 байт, для остальных — 7 680 000. Ошибок и усечения в измеряемых наборах не было. [Старый Python, 40 прогонов](../benchmarks/phase2-reference-8635573.json) · [Новый Python, 40 прогонов](../benchmarks/phase2-optimized.json).

Пик памяти при обходе широкой папки упал примерно на 59%, её список файлов строится на 12% быстрее. Полный обход большого вложенного дерева замедлился на 6–9% в этой серии. Новая проверка подмены каталога делает отдельный вызов `lstat` на каждую папку. Его вклад не измерялся отдельно. В первоначальном аудите старый движок проходил тот же вложенный сценарий за 365,65 мс. В парной серии он прошёл за 273,00 мс, поэтому оценка изменения опирается на одновременно собранную пару. Причина различия между сериями не установлена.

Воспроизведение из текущего дерева в PowerShell. Отдельный исходный каталог нужен, чтобы текущий код и данные не затронуть. Используй новый путь для распаковки, если этот уже занят.

```powershell
New-Item -ItemType Directory -Path dist/phase2-reference-src
git archive --format=zip --output=dist/phase2-reference-src.zip 86355737 tools

  --reference-root dist/phase2-reference-src --reference-output dist/phase2-reference.json > dist/phase2-optimized.json
.venv/Scripts/python.exe -m benchmarks.disk_map --compare dist/phase2-reference.json dist/phase2-optimized.json
```

## Проверки

- Python: 216 прошли, 3 пропущены. Из них один относится к карте диска. `Path.symlink_to()` вернул `WinError 1314`. У текущего пользователя Windows нет права создать символьную ссылку, поэтому интеграционный тест не выполнен. Исключение символьных ссылок проверено с имитацией метаданных. Реальный junction проверен отдельно. Те же права вызвали два пропуска в проверках «Больших файлов» и корзины.
- 91 проверка браузерного интерфейса прошла. В WPF отдельно проверены расчёт через реальный локальный сервер, показ прогресса и остановка при нажатии кнопки и уходе на другую страницу. В HTTP-тесте после отмены проверены освобождение итератора, повторный запуск и ошибка для недоступного пути.
- Проверены широкие папки, глубина 62 уровня, лимиты, отказ в доступе, изменение файла в ходе обхода и между расчётами. На временном томе Windows проверены сумма, пропуск защищённых папок и запрет удаления из корня. Проверка отказа доступа к вложенной папке использует контролируемый `PermissionError`.

## Оставшиеся риски и готовность к Rust

- Отмена кооперативная. Если Windows задерживает системный вызов, обход прекращается сразу после его возврата. Пока вызов занят, второй расчёт не запускается. Дерево, которое меняется во время работы, может дать смешанный по времени результат. Новый запуск заново читает метаданные.
- Полный список файлов всё ещё материализуется, сортируется, сохраняет отпечатки для операций и передаётся целиком. Для сокращения памяти здесь нужна отдельно проверенная пагинация с авторизацией на уровне выдачи. Сериализация, скорость отрисовки, сетевые диски и установленная сборка в Benchmark Lab не измерялись.
- Python-движок готов как точка сравнения для прототипа Rust. Сравнивать следует свежие обходы, применять те же правила для ошибок и усечения, проверять совпадение структуры ответа и измерять полный путь через HTTP с издержками запуска будущего процесса. Перед включением по умолчанию нужны отдельные замеры отмены на медленных дисках, живые символьные ссылки и запуск из установщика.
