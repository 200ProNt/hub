# Расширение Hub в версии 1.6.1

Аудит от 28 ноября 2026 года. База — коммит `6d2a24e8` ветки `codex/hub-1.6`. Проверка рассчитана на одного пользователя Windows 11 x64, локальные данные и отдельный доступ телефона к QR-Drop. Graphify на том же коммите использован для навигации. Выводы о поведении проверены по исходникам.

## Архитектура

| Область | Что есть | Что переиспользуем |
| --- | --- | --- |
| Запуск и поставка | `desktop.py` запускает WPF через Python.NET, локальный HTTP и трей. PyInstaller и Inno Setup собирают установщик. `server.py` также запускает прежний браузерный Hub. | Нативная версия получает новые страницы. Браузерный Hub сохраняет прежние маршруты. |
| Интерфейс | `tools/registry.py`, группы в `native/ui.py`, общие контролы в `native/widgets.py`. Glass и Material используют одни и те же страницы. | Локализация RU/EN, существующие карточки, диалоги, поиск по инструментам и состояния страницы. Регистрация нативных инструментов отдельно от браузерного списка. |
| Выполнение | `Page.run` запускает короткую работу вне потока WPF. `tools/jobs.py` поддерживает одиночное ограниченное задание, прогресс, отмену и аренду, продлеваемую клиентом. | Интерактивные длительные операции используют текущий формат состояний. Фоновые запуски должны жить независимо от страницы. |
| Данные | В настольном Hub файлы находятся в `%LOCALAPPDATA%/Hub/data`. Настройки, корзина и история имеют собственные форматы. Миграция прежнего Hub готовит данные во временном каталоге. | Новые форматы версионируются по мере появления. Данные имеющихся инструментов переносить не требуется. |
| Файлы | `tools/fileguard.py` исключает системные пути и предоставляет отпечатки файлов и папок. Карта диска проверяет объекты при обходе и повторно перед действиями. | Проверка исходных путей и повторная проверка перед изменениями. Блокировки и временные файлы нужны в пределах конкретной операции. |
| Производительность | Python — основной движок. Rust Worker используется для экспериментального подсчёта карты диска. Существуют сравнительные измерения времени, CPU и памяти. | Замеры на одинаковых наборах до выбора движка. Сборка и совместимость Rust проверяются отдельно, когда меняется воркер. |

## Найденные ограничения

1. Общая проверка папки проверяет сам каталог. Если передать обычный подкаталог внутри junction, его родитель может остаться непроверенным. Исправление нужно до внедрения новых операций с файлами.
2. Браузерный запуск слушает все интерфейсы для QR-Drop, а отдельный список разрешённых маршрутов для телефона действует только в настольном режиме. Распространить разграничение на оба режима, сохранив QR-Drop и локальный браузер.
3. Выгрузка данных Hub создаёт весь ZIP в памяти и отдаёт его целиком. Большая корзина повышает стоимость операции. Обычный экспорт данных Hub и новый Backup Manager требуют отдельных проверок пикового потребления памяти.
4. Лимит заданий карты диска и аренда, зависящая от опроса, подходят для расчёта с открытой страницей. По расписанию Hub обязан опираться на сохранённый профиль и проверять предыдущий запуск после перезапуска.
5. Поиск уже умеет находить инструменты, заметки и буфер. Файловый поиск требует собственного локального индекса и отдельно включаемой индексации содержимого.
6. Текущий автозапуск обслуживает запись самого Hub. Монитор получает CPU, RAM, диск и процессы. Экран изображений обрабатывает изображения. Расширения должны использовать эти точки входа и сохранять существующие действия.

## Порядок работ и критерии готовности

| Этап | Результат | Условие перехода |
| --- | --- | --- |
| A · Фундамент | Закрыть обнаруженные разрывы в защите путей и локального HTTP. Зафиксировать контракт фоновых заданий, форматы данных и контрольные прогоны. | Старые настройки читаются. Локальный браузер, WPF и QR-Drop проходят проверку. |
| B1 · Автозагрузка | Источники Run и Startup, источник и путь, статус и издатель при наличии, поиск и сортировка, обратимые действия. | Права Windows соблюдаются. Исходная запись восстанавливается без перезаписи новой записи. Сценарии проверены на отдельных тестовых данных. |
| B2 · Мониторинг | Расширить текущий sampler, добавить ограниченную историю, паузу, интервалы, сетевые, дисковые и GPU-счётчики. | Метрики проверены на доступном оборудовании. Неизвестные датчики помечаются как недоступные. Измерена цена фонового опроса. |
| B3 · Приложения | Инвентаризация и обновления через WinGet, подтверждаемая установка и удаление, прогресс и история. | Проверены отсутствие WinGet, отказ доступа, код завершения, отмена и безопасная передача аргументов. |
| C1 · Файловый поиск | Сравнить поиск по SQLite FTS5 с простым индексом. Добавить выбранные корни, исключения, обновления, паузу и фильтры. | Проверены большой каталог, Unicode, удалённые элементы, обновление индекса и выключенная по умолчанию индексация текста. |
| C2 · Резервное копирование | Профили, версионные манифесты, инкрементальные копии, целостность, удержание, расписание и проверяемое восстановление. | Прерванный запуск виден как прерванный. Подтверждение привязано к плану восстановления. Крупные файлы копируются потоково. |
| C3 · Мультимедиа | Расширить «Изображения» на аудио, видео и PDF. Проверить лицензии и способы поставки инструментов. | Пакетные задания работают с прогрессом и отменой. Подтверждены качество результатов, проверка внешнего процесса и совместимость форматов. |
| D1 · Разработчику | JSON, Regex, Base64, URL, текстовые и кодовые различия. | Проверена отмена зависших регулярных выражений, размер входа, кодировки и экспорт результата. |
| D2 · Автоматизация | Визуальный редактор, условия, история, запуск вручную, по расписанию и по событиям файлов. Использует проверенные операции B/C/D1. | Предпросмотр соответствует фактическим действиям. Подтверждение, отмена и восстановление после сбоя проверены. |
| D3 · Локальный ИИ | Ollama и LM Studio, модели и параметры, помощь с инструментами, структурированные предложения для сценариев. | Подключения ограничены локальным API. Предложения валидируются D2 и проходят пользовательское подтверждение. Hub работает без моделей. |

На исходной версии Windows прогон дал 237 тестов Python, включая 4 пропуска, и 93 успешных теста Node.js. Расширенные проверки Python выполнялись с UTF-8 и разрешённым локальным HTTP, junction и SUBST. Тепловые датчики, WinGet, FFmpeg и модели на этапе аудита не проверялись.

## Выполнено 28 ноября

- **A.** Общая проверка пути теперь проходит все каталоги от корня до выбранной папки и отклоняет junction. Оба режима Hub используют один список LAN-маршрутов для QR-Drop. Фоновые задания и форматы прежних данных переиспользуются. На Windows прошли 235 тестов Python и 93 теста Node.js, 4 проверки Python были пропущены. В Agent Browser открылся QR-Drop, отправился тестовый текст в отдельный профиль.
- **B1.** Менеджер автозагрузки доступен в WPF. Охвачены текущий пользователь, обе ветки HKLM Run и две папки Startup. Изменения требуют подтверждения, обход путей исключается, существующая запись при конфликте сохраняется. Тесты использовали временные записи и реестр-имитацию. Windows-метаданные подтверждены чтением реального исполняемого файла. Медиана проверки 1 001 файла Startup на 7 прогонах составила 69,75 мс по времени, 78,12 мс CPU и 1,59 МиБ прироста рабочего набора процесса. Перенос и возврат файла 256 МиБ с повторным чтением списка заняли 76,65 мс. Запись в реальные системные Run и Startup не менялась.
- **B2.** Монитор читает локальные WMI-счётчики дисков, сети, GPU и выделенной видеопамяти. Температуры ЦП и GPU доступны при наличии провайдера LibreHardwareMonitor. Проверен сценарий, когда этого провайдера нет. В WPF доступны выбор показателей, история из 30 результатов, интервалы 2, 5 и 10 секунд и пауза. Базовый sampler прекращает работу после 12 секунд без запросов. Для одного физического диска, одного сетевого адаптера и двух GPU медианы семи чтений в среде WPF составили 257,45, 258,47 и 341,79 мс. Для GPU в процессе Hub медиана CPU составила 46,88 мс, прирост рабочего набора — 288 КиБ. Замер не включает CPU службы WMI и отрисовку.
- **B3.** Экран «Приложения» подключён к WinGet. Проверены инвентаризация, выделение доступных обновлений и поиск в реальном каталоге WinGet 1.30.310. Установка, обновление, удаление, прогресс и история проверены с тестовым процессом. В Glass и Material проверены отмена подтверждения и передача выбранного пакета. Медианы пяти чтений инвентаря и поиска одного пакета составили 659,41 и 200,66 мс. CPU внешнего WinGet в замер не включён. Все системные инструменты прошли общий прогон: 249 успешных Python, 4 пропуска и 93 успешных Node.js.
- **C1.** Файловый поиск использует SQLite 3.50.4 и FTS5. На 100 000 путей медиана запроса по одному фрагменту составила 0,234 мс через триграммный индекс и 5,602 мс через перебор строк. На папке из 5 001 файла, включая 500 текстов и файл 384 МиБ, первая индексация заняла 5,66 с, повторная — 175 мс, поиск с открытием базы — 8,59 мс по медиане. Прирост рабочего набора процесса при первой индексации составил около 0,96 МиБ. Проверены изменение и удаление, отмена, пауза, opt-in для содержимого, junction и обе темы WPF. Автоматическая проверка выполняется раз в 120 секунд, пока Hub запущен.
- **C2.** Backup Manager создаёт версии с транзакционным манифестом и общим хранилищем блоков SHA-256. Проверены расписание, инкрементальность, исключения, срок хранения, отмена и защита существующих файлов при восстановлении. В обеих темах WPF проверен отказ от перезаписи и подтверждённое восстановление. На файле 384 МиБ создание заняло 841 мс, проверка — 432 мс, восстановление — 1,09 с. Повторная версия записала 0 байт данных и заняла 35 мс. Пиковый рабочий набор измерительного процесса составил 27,9 МиБ. Расписание выполняется при запущенном Hub.
- **C3.** Добавлены пакетные операции видео, аудио и PDF. Проверены настройка разрешения, извлечение аудиодорожки, отмена при кодировании и сохранность исходника на реальном FFmpeg 9.1. Через pypdf 7.1.0 проверены все операции PDF. Поворот подтверждён отрисовкой, а извлечение страницы проверено в обеих темах WPF. Видео 8 с, 720p → WebM 480p заняло 20,60 с, 23,56 с CPU и 207,1 МиБ пиковой памяти FFmpeg. MP3 из этого видео занял 575 мс, 156 мс CPU и 20,1 МиБ пиковой памяти FFmpeg. Поворот 1 000 страниц PDF занял 361 мс, 281 мс CPU и 10,39 МиБ прироста рабочего набора Hub. Windows ZIP собрался с лицензией pypdf. FFmpeg подключается отдельным установленным комплектом.
- **D1.** Работают JSON, Regex, Base64, URL, сравнение текста и файлов с кодом. В WPF проверены JSON с указанием позиции ошибки и Regex с именованными группами в обеих темах. Потоковый Base64 на файле 256 МиБ занял 1,81 с на кодирование и 1,88 с на декодирование. CPU составил 1,33 и 1,67 с, пик рабочего набора процесса — около 29 МиБ.
- **D2.** Сценарии переиспользуют сортировку, очистку, сжатие изображений и Backup Manager. Проверены ручной запуск, расписание, изменения выбранной папки, условные шаги, пауза, отмена и история. Перенос в корзину выполняется по подтверждённым файлам с проверкой состояния после предпросмотра. В обеих темах WPF проверена реальная сортировка. На 1 000 файлах предпросмотр занял 517 мс, запуск — 7,52 с, CPU — 453 мс и 4,97 с. Рабочий набор вырос на 2,46 МиБ при предпросмотре и ещё на 0,63 МиБ при запуске. Разделены журналы «Дубликатов» и «Уборки».
- **D3.** Подключены Ollama и LM Studio REST API v1. Локальные тестовые HTTP-серверы подтвердили список моделей, настройки генерации, прекращение ожидания по отмене, отклонение удалённого адреса и отказ от небезопасного черновика. В обеих темах проверена передача валидного черновика в редактор без записи или запуска. Параметры подключения сохраняются локально. Токен и запросы Hub не сохраняет.

## Итоговая проверка Windows

Прошли 282 теста Python, ещё 4 пропущены. Все 93 теста Node.js прошли. В прогон
вошли живые тесты FFmpeg 9.1. Собран предварительный Windows ZIP с внутренней
версией 1.6.0. Проверены CRC архива, комплектность и лицензия pypdf. Из отдельного
профиля Hub открыл окно, ответил по локальному API с путём к проверяемой сборке
и штатно завершился. SHA-256 архива
`3967982240CBF7FD9E52C39DBB95DD7F56059D9E0983E4B44025DAEECE67E303`.

Реальный LM Studio на этой машине ответил на пробный запрос за 8,47 с, включая
холодную загрузку модели. Клиент Hub затратил 15,6 мс CPU и 16 КиБ рабочего
набора. Показатели процесса LM Studio в замер не входят. Тестовый экземпляр
модели выгружен после прогона. Ollama проверена на локальном тестовом сервере.

Инвентаризация и поиск WinGet проверены на установленной версии. Изменения
пакетов и системных записей автозагрузки проверены на тестовых данных.
Температурный провайдер на этой машине недоступен. Расписания выполняются при
запущенном Hub. Архитектурный граф обновлён до 2 644 узлов и 6 554 связей по коду.
